## 1. 병목 ① 로그인 쿠키 — 세 갈래와 권장안

수강편람 내부 API 는 학사 계정 세션(`JSESSIONID`)이 있어야 응답합니다. 자격증명·쿠키는
공개 저장소·Actions Secrets 에 둘 수 없다는 원칙(계획서 2절 4)은 그대로입니다.

| 갈래 | 내용 | 장점 | 위험·비용 | 판정 |
| --- | --- | --- | --- | --- |
| **A. 세션 유지(keep-alive)** | 사람이 학기에 한 번 로그인하면, 로컬 데몬이 10분마다 가벼운 API(학기 목록 조회)를 호출해 세션을 살려 둔다 | 코드 반나절, 계정 위험 없음, 서버 부하 무시 가능(시간당 6요청) | 만료가 **무활동 타임아웃**이어야만 성립. 절대 만료(SSO 토큰 수명)면 무효. 서버 재시작·학교 정책으로 끊길 수 있음 | **실험 후 결정** (P3-0) |
| **B. 학교 협의** | 학과 행정을 통해 정보화 부서에 읽기 전용 계정 또는 데이터 제공(CSV·API)을 요청 | 정공법, 장기적으로 유일하게 깨끗한 해법 | 기간·성사 불확실, 담당자 노력 | **병행 추진** (P3-6) |
| **C. SSO 자동 로그인** | headless 브라우저로 ID/PW 입력 | 완전 무인 | 계정 잠금, 약관 위반 가능, NetFunnel 대기열, 비밀번호 보관, 실패 시 복구 비용이 이득보다 큼 | **비권장 유지** — 별도 계정 + 학교 승인 시에만 재검토 |

### P3-0 세션 수명 실험 (0.5일 · 사람 로그인 1회)

1. 로그인 → 쿠키를 로컬 데몬(`tools/automation/session-keepalive.mjs`, 크롤러 `api.js`
   재사용)에 넣는다. 데몬은 10분마다 `findMlgSyySmtDivCdList` 를 1회 호출하고 응답이 JSON 인지
   기록한다(`.state/keepalive.log`).
2. 24시간·72시간 시점의 생존 여부로 판정한다.
   - **살아 있음** → 만료는 무활동 기준. A 채택: 학기 초 로그인 1회로 학기 전체를 덮는다.
     데몬이 죽음을 감지하면 이슈 `[자동] 수강편람 로그인 필요` 를 만들고 이후 단계는 대기.
   - **죽음** → 절대 만료. A 폐기, 현 반자동(리마인더 → 로그인 → 실행) 유지 + B 추진.
3. 매너: 요청 1개/10분, 식별 가능한 UA, 학교 측 요청이 있으면 즉시 중단. 크롤 자체는
   기존 매너 규칙(순차·300ms) 그대로.

> 이 실험이 Phase 3 전체의 분기점입니다. 성공하면 2·3 은 "학기 1회 로그인" 만 남고,
> 실패해도 아래 ②③ 은 그대로 유효합니다(사람 시간의 대부분은 ②③에 있습니다).

## 2. 병목 ② 실행 주체와 판단 — 과목 카탈로그·마일리지

### P3-1 교수 보강표 자동 축적 (S · 즉시 · 무위험)

`professor-history.csv` 가 수기인 이유는 **과거 학기 라인업을 크롤 시점에 기록하지 않았기
때문**입니다. 크롤 레코드에는 그 학기의 담당 교수가 있으므로, 오케스트레이터 ⑤ 단계에서
`(year, semester, code, division, professor)` 를 CSV 에 자동 append 하면 다음 학기부터는
보강이 필요 없습니다(이미 있는 행은 건너뜀, 사람이 적은 행은 우선). `RECENCY_ALIAS` 는
특정 학기 라인업의 예외 보정이라 자동화하지 않고, 값이 남아 있으면 ⑩ 에서 "재검토" 한 줄만
찍습니다.

### P3-2 백테스트 채택 규칙 코드화 + 봇 PR (M)

- 채택 규칙(초안): 공통 분반 기준 **MAE 악화 ≤ 0.10점 이고 Hit±3 하락 ≤ 0.5%p** 이면 채택,
  아니면 중단 + 이슈. 근거: 2026-20 재생성 실측(MAE 4.23 / Hit 65.0%)에서 데이터가 늘어
  나빠지는 일은 드물고, 규칙의 목적은 개선 판정이 아니라 **크롤이 깨진 채 병합되는 사고를
  거르는 것**입니다. 두 학기 운영 후 수치를 조정합니다.
- 통과하면 오케스트레이터가 산출물(체커 3 + 마일리지 3~4 + CSV)을 **봇 브랜치
  `bot/semester-<term>` 에 커밋하고 PR** 을 만듭니다. PR 본문 = 게이트 결과 + 백테스트 표 +
  `rename-report.json` 요약. main 직접 커밋 금지 원칙은 그대로이고, 사람의 일은 **머지 1클릭**
  으로 줄어듭니다(Vercel 이 main 푸시로 배포).
- 개명 게이트 실패(요건 과목 이름 변경)는 자동화하지 않습니다 — 별칭 판단은 사람 몫이고,
  실패 시 이슈로 멈춥니다. 다만 리포트의 `curatedRenameRequired` 를 이슈 본문에 그대로
  실어 판단 시간을 줄입니다.

### P3-3 로컬 러너 스케줄 + 쿠키 상태 이슈 (S~M)

- 실행 주체는 **로컬 러너**(쿠키가 있는 곳)입니다: 사용자 PC 의 작업 스케줄러, 또는 상시
  켜진 소형 VM(월 수천 원)에 GitHub self-hosted runner. 공개 저장소의 호스티드 러너에는
  쿠키를 보낼 수 없습니다.
- 리마인더 날짜(12/1·1/15·6/1·7/15)에 러너가 `update-semester.mjs --target <term>` 을
  자동 실행합니다. 쿠키가 없거나 만료면 이슈 `[자동] 수강편람 로그인 필요 (<term>)` 를 만들고
  **매일 재시도**합니다(A 채택 시 keep-alive 데몬이 이 이슈를 대신 관리).
- 러너의 실행 로그·상태 파일은 PR 본문에 요약만 싣습니다.

### 이 단계가 끝난 뒤 사람이 하는 일

| 항목 | A 성공 시 | A 실패 시 |
| --- | --- | --- |
| 로그인 | 학기 1회(데몬이 요청하면) | 학기 1~2회(리마인더 이슈가 요청하면) |
| 실행·검증·산출물·커밋 | 없음(봇 PR) | 없음(봇 PR) |
| 판단 | PR 머지 1클릭, 개명 게이트 실패 시 별칭 | 같음 |

## 3. 병목 ③ 입학 캘린더 반영 — 감지에서 PR 까지

지금 감시 워커는 변경분을 **우리 스키마 JSON 조각**까지 만들어 이슈에 싣습니다. 남은 것은
그 조각을 파일에 넣고, 영문을 채우고, 커밋하는 손일입니다. 셋 다 자동화됩니다.

### P3-4 캘린더 PR 자동 생성 + 영문 자동 번역 (M)

- **패치 생성**: 워커가 `content/admission-guide.json` 의 `calendar.events` 를 사이트 기준으로
  갱신한 파일을 만든다 — 기존 이벤트는 `date + 정규화 제목` 키로 찾아 `lines` 를 갱신, 새
  이벤트는 추가, 사라진 이벤트는 삭제 후보로 표시(삭제는 PR 본문에 따로 나열).
- **영문**: 관리자 콘솔이 쓰는 `src/lib/admin/translate.ts`(DeepL, `DEEPL_API_KEY`) 로직을
  Node 스크립트에서 재사용한다. 전형명·트랙명은 기존 `en` 값에서 뽑은 **용어집을 우선**
  적용해(수시모집=Early Admission (Susi) 등) DeepL 이 고유명사를 흔들지 않게 한다.
  키 위치: 호스티드 러너면 Actions Secrets(무료 키 권장, fork PR 에는 전달되지 않음),
  로컬 러너면 `.env.local`.
- **PR**: 변경이 있으면 이슈 대신 브랜치 `bot/admission-<date>` 에 커밋하고 PR 을 연다.
  diff 가 곧 리뷰이고, 본문에 원문 링크·변경 분류·미대응 항목을 싣는다. 이슈는 "감시 실패"
  에만 남긴다.
- **원칙과의 관계**: "무검수 자동 반영 금지"는 **머지를 사람이 한다**로 지킨다. 사이트의
  disclaimer("입학처 공지 기준, 세부 시간·장소는 변경될 수 있음")는 그대로 둔다.

### P3-5 (조건부) 자동 머지 (S · 운영 실적 후)

두 달 이상 PR 이 문제없이 머지되면, **위험이 낮은 변경 등급**만 자동 머지를 허용합니다:
기존 이벤트의 `lines` 문구 변경(시각·장소)이고 이벤트 추가·삭제·트랙 변경이 없는 PR.
그 외는 계속 사람 머지. 자동 머지도 typecheck 등 CI 통과가 조건입니다.

### 연 1회 전면 재작성의 자동화

새 학년도 캘린더가 게시되면(모집요강 공표 후 4~6월) 워커가 `s_year=YYYY+1` 의 이벤트 수
증가를 감지합니다. 그때 `calendar.year`·`intro` 의 연도를 바꾸고 이벤트를 새 학년도로 채운
**전환 PR** 을 자동 생성합니다. 4/25 리마인더 이슈는 이 PR 이 뜨면 자동으로 닫습니다.

### 이 단계가 끝난 뒤 사람이 하는 일

PR 머지(P3-5 후에는 저위험 변경은 그것도 없음), 미대응 트랙(정시·편입 등 우리 범위 밖)
편입 여부 판단.

## 4. 부록 — 교재(4)는 ① 이 풀리면 같이 열린다

교재를 제외한 이유는 크롤 코드 부재와 규모였지만, 근본 원인은 수업계획서가 **같은 로그인
세션**이 필요한 PDF 렌더링이라는 점입니다. ① 이 풀리면: 같은 쿠키로 ClipReport PDF 를 받아
텍스트를 추출하고(교재 표 파싱) → ISBN 정규화 → 표지(교보 CDN + 대체 출처) → 기존
`build-content.mjs` 로 이어 붙일 수 있습니다. 규모 M~L, 별도 계획으로 다룹니다 — 착수 여부는
사람의 결정입니다.
